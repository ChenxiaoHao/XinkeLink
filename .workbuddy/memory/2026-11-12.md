技术经验（重要，避免重复踩）：
- `batch_edit` 里 binding 作 parent **不能加引号**：`I(es, {...})` 对，`I("es", {...})` 报 parent not found。
- `Copy` 的 `descendants` 用源节点 ID 无效（报 `Copy descendant not found: 新ID/旧ID`），必须复制后先 `batch_read` 拿新 ID 再 `U`。
- `U()` **改不了 `svg` 属性**（返回 `updated:{}`），要换图标只能 `D` 删除再 `I` 重建，然后用 `M` 调回兄弟顺序。
- 我写的第一版齿轮图标是「圆+8条放射线」，渲染出来是太阳，已换成 lucide settings 路径。
- 通知行内容区实测很窄（375 - 32 padding - 20 类型图标 - 36 头像 - 56 缩略图 - gaps ≈ 200），长昵称会把右侧时间戳挤掉，设计稿里要用短昵称，落地代码需要给昵称加 ellipsis + 时间 `flex:none`。

六屏共同决策：分段 tab / 抽屉菜单 / 主页 tab 全部只放后端真有的维度，不做假按钮；主页与抽屉用「动态数 / 获赞数」替代 X 的关注数字。

新增踩坑（重要，下次直接用）：
1. `batch_edit` 的 operations 是**逐行解析**的：不能带分号 `;`，不能 `var`，不能多行语句。正确写法 `p1=I("2:225",{...})` 一行一条，返回 `expiredBindings` 说明本行变量下一批失效。
2. `fills` 的 color **必须是 {r,g,b} 0~1 对象**，传 `"#1D9BF0"` 会报 `Expected object at [0].color`。
3. 往不存在的 id 插入**不会报错**，节点会挂到树上某个无关节点甚至 Rectangle 下变成孤儿（我把账号组插进了状态栏 WiFi 图标的 Rectangle 里）。一定要用变量承接父节点 id，别硬编码猜 id。
4. `type:"frame"` + `svg` 属性可以画图标，svg 会被自动转成 VECTOR 子节点；2 条 path 的返回箭头就变成 2 个 Vector。想复用已有图标直接 `C(图标节点id, 目标父节点)` 复制，比抄 svg 稳。
5. 文字换行只要 `width:"fill_container"` + `height:"hug_contents"`，不需要 textGrowth。
6. 行内文字行高用 `lineHeight:{value:20,unit:"PIXELS"}`；同一行里字号更大/行高更大的文字会溢出父 frame 1px，父 frame 高度要按最大行高给。
