# 信科 Link 技术架构

依据：2026-10-22 用户最终指定方案。本文取代此前提出的 NestJS、PostgreSQL 和共享类型 workspace 建议。原 README.md 保留。

## 产品边界

- 河南信息科技学院学生校园社区微信小程序，配套独立 PC 管理后台。
- 五栏入口：论坛、交易、中央发布、联系、我的。
- 论坛为动态信息流，不引入话题广场或 #话题。
- 交易通过私信沟通、当面验货与线下成交，不引入在线支付、购物车、担保交易。
- 匿名帖公开响应不暴露真实作者；普通身份文案不能暗示学校官方认证。
- 业务页面依据用户提供的 Stitch 材料逐批实现。

## 技术组合与数据流

| 工程 | 技术 | 依赖管理 |
| --- | --- | --- |
| apps/miniprogram | 原生微信小程序、TypeScript、WXML/WXSS | 独立 package.json / package-lock.json |
| apps/admin | Vue 3、TypeScript、Vite、Element Plus | 独立 package.json / package-lock.json |
| apps/server | Java、Spring Boot、Maven | 独立 pom.xml |
| 数据库 | MySQL | 在持久化阶段引入连接配置与迁移 |
| 私信 | 标准 WebSocket + HTTP 历史消息接口 | 消息持久化到 MySQL |
| 图片 | Java ImageStorage 接口 | 具体服务后续确定 |

三个工程独立安装、启动和构建；不建立共享类型包或额外 monorepo 构建工具。后续接口契约以服务端接口文档为准。

小程序与后台通过 HTTP 访问 Java 服务。服务按登录、用户、论坛、交易、消息、通知公告、举报与管理权限划分业务模块，先保持一个服务端应用。

私信阶段先把消息写入 MySQL，再返回确认并推送；HTTP 提供分页历史和断线补取。第一阶段不建立真实连接或消息表。

图片业务依赖 ImageStorage。接口约定上传输入、存储标识、访问地址与删除操作，不绑定厂商 SDK。第一阶段不暴露上传端点或配置生产凭据。

第一阶段只启动健康接口，不依赖数据库、聊天或外部存储。健康正常只表示 Java 服务运行。

## 目录职责

~~~text
apps/miniprogram/   微信小程序、原生组件、设计变量与组件测试
apps/admin/         Vue 最小启动页、Element Plus、主题与连接检查
apps/server/        Spring Boot、健康接口、存储接口及集成测试
docs/               架构、设计依据、计划、运行与验收记录
scripts/            统一检查入口
~~~

## 开发阶段与验收

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 1 工程与公共 UI | 三个工程、变量、五栏导航、发布面板、健康及存储接口 | 类型检查、前端构建、Java 测试打包与启动；微信工具、视觉与真机结果单独记录 |
| 2 首批页面 | 按高清稿逐批还原论坛、交易、联系、我的及详情 | 同尺寸截图对照；操作、返回、滚动、安全区检查 |
| 3 论坛与用户 | 登录、资料、帖子、评论回复、点赞收藏、匿名 | 真实数据库流程、越权、匿名信息与异常检查 |
| 4 交易与私信 | 商品管理、WebSocket、历史消息、关联商品 | 双账号沟通、持久化、补取、去重、商品归属 |
| 5 管理闭环 | 内容、用户、商品、举报与公告 | 权限、处理记录、小程序状态同步 |
| 6 发布验收 | 搜索、举报、预览、异常状态与部署 | 页面清单、微信真机、配置与核心流程回归 |

每阶段仅声明实际执行的验证。第一阶段交付运行说明与结果后，再推进第二阶段。
