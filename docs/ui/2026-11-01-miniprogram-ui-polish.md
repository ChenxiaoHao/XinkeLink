# 信科 Link 小程序全页面 UI 优化交付记录

完成日期：2026-11-01。

本轮按用户截图确认的原方案实施，使用 **emil-design-eng + ui-ux-pro-max**。范围为小程序 19 个已注册页面及其公共组件；没有采用后续提出的头像侧栏布局，也没有将生成的效果图作为已实现画面。

## 已完成的改动

| Before | After | Why |
| --- | --- | --- |
| 举报原因、聊天设置操作为居中的窄按钮 | 全宽列表行、正常字重、统一左右对齐和点击区域 | 修复已实际测量的布局缺陷 |
| 搜索历史词撑宽居中 | 按内容宽度左对齐；清空保留在右侧 | 消除微信默认按钮样式影响 |
| 首页、详情、搜索、个人列表的帖子与商品卡片规格不同 | 共用字号、元信息色、互动图标与热区；图片失败提示覆盖非首页 | 提升跨页面一致性 |
| 帖子、商品用心形，评论用拇指 | 评论同样使用描边/填充心形，保持真实服务端点赞状态 | 同一语义使用统一图标 |
| 主页面重复显示品牌与大标题 | 论坛将搜索并入品牌头部；交易保留宽搜索并移除重复标题；联系将全部已读并入 Tab 行 | 降低顶部堆叠 |
| 个人中心统计条与菜单重复 | 数量并入“我的帖子、我的闲置、我的点赞”，关于收在设置，移除重复页脚 | 保留原入口与真实数字，减少重复内容 |
| 发布帖子分成多张卡片，发布按钮独占一行 | 连续白底编辑区，发布/保存并入头部并避让胶囊 | 编辑更连贯 |
| 发布闲置仅靠 placeholder 表达部分字段 | 增加固定字段标签，按图片、信息、价格/条件组织，保留草稿和校验 | 输入后仍知道字段用途 |
| 商品详情多层浮动卡片与重复安全说明 | 图册、价格/标题、卖家、描述依次排列，安全提示集中呈现 | 突出物品、价格和卖家 |
| 聊天时间格式不一致 | 两种聊天共用时间格式及五分钟分组，保留双方头像昵称，正常发送状态降低权重 | 聚焦消息正文，不伪造“已读” |
| 弹层只有入场，关闭立即移除 | 进入/退出及遮罩过渡统一，退出后卸载，快速重开取消旧关闭任务 | 避免突然消失或被旧定时器误关闭 |

公共规范保留 Logo、主色 `#6489B8`、五栏导航布局和中央发布按钮。阅读区以白色为主，背景使用中性浅灰；正文、辅助字、图标、间距与圆角统一。普通卡片取消无意义阴影，按压反馈幅度减小，并提供减少动态效果的样式。

19 页覆盖：论坛、帖子详情、发布/编辑帖子、交易、商品详情、发布/编辑闲置、我的闲置、联系（私信及通知）、普通聊天、商品聊天、聊天设置、我的、我的帖子、我的点赞、个人主页、编辑资料、设置、搜索、举报。发布/编辑复用原页面，没有增加业务页面。

## 业务保护

- 继续使用原真实 API，不接回模拟数据，不更改服务端协议。
- 点赞、取消点赞仍按服务端结果局部更新，不整页刷新。
- 搜索仍由确认键或历史词点击触发；没有加回搜索发现、大家在搜。
- 登录、微信头像选择、昵称输入及资料确认规则保留；本轮没有代替用户授权。
- 匿名规则、用户自填声明、学号仅本机保存边界保留。
- 删除、下架、屏蔽、举报等原有确认与权限逻辑保留。
- Java 服务端、PC 管理后台、OSS、数据库与迁移没有修改。没有 Git commit、push、reset、clean。

`miniprogram/backend/pages.ts` 的变化仅为客户端聊天时间呈现，不是 Java 后端业务修改。
