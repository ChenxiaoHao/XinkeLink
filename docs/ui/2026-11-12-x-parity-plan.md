# 信科 Link 小程序：全面对齐 X 的整体方案

日期：2026-11-12　范围：`apps/miniprogram` 界面重构 + 必要的后端补充　状态：方案待拍板，未改动代码

## 0. 一句话结论

五个底部入口（首页／搜索／Link AI／通知／私信）和抽屉、帖子卡的**骨架上一轮已经按 X 搭好了**，但 11-11 之后又做了半截改造：工程当前**编译不过**、二手交易残留未清、32 个样式文件里 20 个还是旧的 rpx + 旧蓝体系。所以这次不是"从零仿 X"，而是**三步**：先把烂尾基线修绿 → 把设计系统和组件层一次性换掉 → 再逐屏对齐 8 张参考图。

真正缺的不是像素，是两块能力：**关注关系**和**转发／引用**。X 的心脏是关注时间线，没有它，"正在关注"永远是空壳、抽屉里的关注数永远是 0。

## 3. 功能对账与三档策略

原则沿用项目既有的 QA 规矩：**不放假按钮、不编数字**。所以 X 的每个模块先归到三档之一。

### A 档：真做（后端已有）

发帖、时间线（推荐/最新）、点赞、评论与回复、收藏（书签）、分享、私信、通知、公告、搜索与趋势（用帖子里的 `#话题` 实时聚合，已是真数据）、个人主页（自帖、媒体）、编辑资料、设置、反馈、举报、草稿（本地）。

### B 档：补最小后端，建议做

| 项 | 为什么值得做 | 改动量 |
|---|---|---|
| **关注／取关 + 正在关注时间线 + 关注数** | 没有它 X 就只是个论坛；做完"正在关注"tab、抽屉关注数、主页关注数、推荐关注卡、`follow` 通知全部变真 | 迁移 V10 + 4 个接口 + 通知类型 + 前端 1 天 |
| 主页「回复」tab | X 主页四 tab 的第二个，缺了主页不成立 | 一个 `GET /users/{id}/comments` |
| 主页「加入时间」 | 图 2 有「2026年6月 加入」，`xl_user.created_at` 已经在库里，只是没投影 | 加 1 个字段 |

### C 档：明确不做（但视觉上要交代清楚）

| X 模块 | 处理方式 |
|---|---|
| 订阅 / Money / 社群 / 列表 / 空间 / 创作者工作室 | 抽屉里**保留位置但打「建设中」灰色小标签**，点击弹一个统一的"功能路线图"半屏（说明当前只有校园动态与私信）。视觉 1:1，语义不撒谎 |
| 转发 / 引用帖 | 帖子卡上的转发位改为**"分享/复制链接"**（真功能），不做转推 |
| 认证蓝标 | 不做假标。换成中性的「自填资料」灰标签，和现有"未经平台核实"口径一致 |
| 新闻 / 体育 / 娱乐 趋势 tab | 换成真维度：**探索 / 趋势 / 帖子 / 用户** |
| 视频、直播空间 | 不做，只做 1–9 图 |
| Grok Bot | 复用 Link AI 页，状态如实显示"接入中" |
| 浏览历史 | 本地 storage 真做（不联网），抽屉「历史」指向它 |

## 8. 三个技术判断，请先确认

1. **统一 px，废弃 rpx 与 tablet-scale 媒体查询**。X 的尺寸本来就是 CSS px，rpx 会在不同宽度上等比放大，反而失真。保留 `max-width:460px` 居中给平板/PC 预览。
2. **间距优先用 margin，不用 `gap`**。小程序 `flex gap` 在部分 iOS 旧版与安卓存在塌陷，关键排版不能赌。现有 `app-shell` 已在用 `gap`，改造时统一回 margin。
3. **drawer / sheet 用 transform + opacity，不用 `display`**。避免 X 那种丝滑位移在小程序里变成闪跳；`will-change` 慎用，小屏内存吃紧。
