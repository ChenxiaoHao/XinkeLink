# 内测准入与内测码管理

用户已确认实施范围：30 个内测码、登录后的内测准入页面、后台阶段/余额/列表/绑定账号，以及用 2 个码完成验证。用户后续明确新增界面采用黑白风格、去掉蓝色；本次内测准入页面及其头像昵称确认使用局部黑白主题，后台保持既有黑白风格。不重做其他页面，不增加学生认证、缓存、抽奖或 AI，不部署公网。

## 用户规则

- 内测时先微信登录，再兑换内测码。一码一账号、一账号一码；成功后跨设备重新登录仍有效，不重复消耗。
- 未激活账号及访客不能读取业务内容、图片或建立 WebSocket。认证、内测状态/兑换、本人资料完善是必要例外，管理员后台始终可访问。
- 30 个码由管理员首次初始化时用安全随机数生成并持久化；再次初始化不会追加、重置或消费。完整码只在管理员接口与后台展示，日志/公开接口不返回码表，不放入前端源码。
- 后台显示内测/开放阶段、总数、已用、剩余、30 个码的状态、账号 ID/昵称及使用时间；可复制未用码、筛选、搜索和刷新。
- 管理员确认后可切换阶段。开放时恢复现有业务访问策略；已有账号及码绑定记录保留。重新开启内测时立即恢复准入要求。
- 按授权创建两个明确标记的验证账号并兑换两码；最后实际内测批次总数 30、已用 2、剩余 28，不清理既有数据。

## 固定接口契约

响应沿用 ApiResponse。时间为 UTC ISO 字符串，所有 ID 用十进制字符串。

- `GET /api/v1/beta/access`（可匿名）：`{phase:'beta'|'open',authenticated:boolean,activated:boolean}`。
- `POST /api/v1/beta/redeem`（用户）：`{code:string}`，返回上面的准入状态。
- `GET /api/v1/admin/beta`（管理员）：`{phase,version,total,used,remaining,codes:[{id,code,status:'unused'|'used',user:{id,nickname}|null,usedAt:string|null,createdAt:string}]}`。
- `POST /api/v1/admin/beta/initialize`（管理员，空 JSON）：原子初始化固定 30 个码并启用内测，返回完整管理结果；重复调用只返回已有批次，不更改阶段。
- `PATCH /api/v1/admin/beta`（管理员）：`{phase:'beta'|'open',expectedVersion:number}`，返回完整管理结果。版本冲突沿用 VERSION_CONFLICT；启用前必须已初始化。
- 内测拒绝返回 `403 BETA_ACCESS_REQUIRED`；错误或已被其他人使用的码返回 `400 BETA_CODE_UNAVAILABLE`，不泄露归属；兑换使用现有 Redis 限流，账号/IP 双维度。
- 码格式建议 `XK-XXXXXX-XXXXXX`，忽略大小写、空白和分隔符。已激活账号重试或误填其他码不消耗新码。

## 实现边界

- 新增 Flyway V7，只创建内测阶段和内测码两张表；历史迁移不可修改。初始阶段 open、无批次，由本轮验证完成后显式初始化并开启当前开发库，避免迁移过程暗中生成不可分发的码。
- MySQL 事务、账号/码行锁及唯一约束保证同码并发只有一人成功、同账号并发不多领。权限在服务端统一检查，同时保护 HTTP、图片与 WebSocket。
- 保留头像昵称原生确认流程；未激活时仅允许必要的本人资料 GET/PATCH 和头像上传，不开放内容上传或其他业务。mini 的准入页/重定向由服务端状态决定，不信任本机 activated 标记。
- 小程序增加 `pages/beta-access/index`。冷启动、分享直达、旧会话、错误回跳均受控；登录取消、错误码、网络失败、重复点击有清楚反馈。已激活或开放时转入原页面（安全校验的站内目标）或论坛。
- 后台沿用现有导航、表格、字体和单色样式；增加“内测管理”页面，顶栏显示真实阶段。加载失败不伪装为 0 个码或“正式开放”。
