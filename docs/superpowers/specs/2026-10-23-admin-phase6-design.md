# 信科 Link PC 管理后台第六阶段设计规格

## 目标与范围

本阶段仅完成“操作日志”和“系统设置”。继续使用现有 Vue 3、TypeScript、Element Plus、Pinia 与本地模拟数据；不接 Java 后端，不改小程序，不实现真实服务器、Redis、数据库清理、AI 审核或微信消息能力。刷新页面后模拟状态恢复初始值。

## 结构与数据流

新增一个 Pinia 操作日志 store，作为跨模块的只读事件账本。帖子、评论、商品、举报、用户、公告、通知管理中成功完成状态变更后，向它追加一条事件。事件包括唯一 ID、时间、操作者、业务模块、操作类型、目标类型与摘要、结果，以及允许展示的字段名列表。管理员登录 store 增加仅保存在内存中的当前账号标识，登录成功时设置、退出时清除；操作者取此标识，若当前会话无账号名则显示“本地演示管理员”。事件不保存密码、Token、帖子/评论正文、通知正文或配置值。

日志接入放在各业务 store 的变更边界：只有实际尝试的管理动作才形成事件；成功或失败结果必须如实标记，不伪造成功记录。举报处理同步修改关联业务对象时，记录一次“举报处理”主事件，并在同一摘要中说明受影响的目标，避免把一个审核动作误报成多个独立管理员操作。系统设置保存和恢复默认值也通过相同日志 store 记录，摘要只列变更字段名称，不包含配置前后值。

新增本地系统设置 store，集中维护 Stitch 设计范围内的平台基本信息、内容审核规则、社区管理规则、管理员展示信息和系统基础参数。只保存可编辑的模拟配置；品牌名称固定为“信科 Link”，学校信息只作为平台服务范围展示，不宣称学校官方身份。管理员信息仅展示安全的账号标识和角色，不存储或回显凭据。保存前进行字段校验；恢复默认值须二次确认。保存/恢复及校验失败均给出明确反馈。

## 页面与交互

- 将现有“开发中”占位路由替换为操作日志页和系统设置页，保留已验收的后台固定侧栏、固定顶栏及右侧独立滚动结构。
- 操作日志页提供统计卡片、关键词、管理员、业务模块、操作类型、日期范围筛选、分页、只读详情抽屉和导出当前筛选结果 CSV。无结果与清空筛选状态明确可见。
- CSV 使用 UTF-8 BOM、标准字段转义，并对以 `=`, `+`, `-`, `@` 开头的单元格加安全前缀，避免表格软件将内容当成公式。导出字段不包含敏感值。
- 系统设置页按 Stitch 的分组展示与编辑字段，提供保存、恢复默认值和对应确认弹窗；危险操作只限恢复本地默认配置，不提供清空数据或删除内容的按钮。
- 两页复用现有公共卡片、表格、抽屉、表单和提示样式，不调整 Dashboard、登录页或其它模块布局。

## 脱敏与约束

日志事件只接受显式白名单字段，不接收整份表单或任意业务对象。追加前移除疑似密码、Token、密钥、Cookie、Authorization、手机号、学号等值字段；若摘要中检测到凭据模式则替换为 `[已脱敏]`。CSV 与详情抽屉使用同一安全投影。设置日志记录字段名及动作，不记录具体值。日志 store 不提供编辑或删除动作。

## 验证

1. 单测覆盖事件白名单/脱敏、筛选与分页、CSV 转义、设置校验与默认值恢复。
2. 集成测试验证帖子、评论、商品、举报、用户、公告、通知的已完成状态变更会追加日志，设置保存/重置会产生日志且不泄露配置值。
3. 运行 TypeScript 检查、全部 Vitest 与生产构建。
4. Playwright 验证日志查询、筛选、详情、导出、跨模块记录，以及设置保存、校验、取消/确认恢复默认值；在 1366px 和 1440px 检查固定导航与独立滚动。
5. 保存操作日志列表、详情、系统设置、配置确认弹窗的浏览器截图，并报告仍未覆盖的真实后端行为。

## 实施顺序

先确认现有登录 store、业务 store 及路由入口；再增加日志与设置 store 及单测；依次接入已有管理操作；实现日志页和设置页；最后运行全部自动检查及浏览器验收。保持现有工作区改动，不执行 Git 写操作。
