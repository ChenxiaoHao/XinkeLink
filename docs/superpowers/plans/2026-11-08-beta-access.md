# 内测准入实施计划

依据：[已确认范围与接口设计](../specs/2026-11-08-beta-access-design.md)。用户明确授权实施，继续在保留所有未提交成果的当前 codex/phase-1-foundations 工作区完成，不创建新 worktree、不提交或推送。

## 任务与所有权

1. 服务端：新增 V7、beta 包、管理/用户接口、HTTP/图片/WS 准入、兑换限流；更新迁移与契约测试，适配数据库权限脚本。仅编辑 apps/server 与确有必要的 scripts。
2. 管理后台：新增服务/store/内测页面/导航/顶栏阶段，使用固定接口契约；先写业务与浏览器测试；仅编辑 apps/admin。
3. 小程序：新增准入页面及冷启动/分享路径拦截，保留微信头像昵称流程；先写测试，再实现；仅编辑 apps/miniprogram。
4. 集成：主执行者复核三端契约、运行常规检查和隔离数据库/浏览器/官方编译；检查权限绕过、并发和状态切换，修正问题。
5. 实际批次：当前开发库备份、迁移、最小权限授权、正常服务启动；通过测试 classpath 生成两个明确标记的验证身份与会话，正常 API 初始化 30 码并兑换 2 码。校验 30/2/28、绑定和后台实际页面；不修改旧用户/帖子/商品。
6. 记录与交付：更新 API 契约与本轮验证报告，提供页面/截图/查看入口；明确真实微信/真机验证边界，所有原始码只在后台或本机私有文件中。

## 执行约束

三端使用同一契约，互不编辑其他端文件。测试数据库使用明确 _test 名称；不得对原库运行治理回归、repair/clean、删除或重置。独立进程用隐藏窗口并记录 PID，端口占用时不停止未知进程。库权限维持运行/迁移账号分离，审计表只追加。阶段切换只由明确管理操作执行。保留测试失败证据，不把模拟 wx 账号称作真实微信授权。
