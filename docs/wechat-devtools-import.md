## 2. 导入已有工程

1. 打开本机微信开发者工具，用微信扫码登录。
2. 进入“小程序”项目列表，选择“导入项目”或“导入已有项目”（名称以当前版本界面为准）。
3. 项目目录选择 D:\CODE\XinKeLink\apps\miniprogram。
4. 项目名称可填写“信科 Link”，以导入原有工程的方式打开。

目录层级如下：

~~~text
D:\CODE\XinKeLink\apps\miniprogram\     ← 选择这一层
├─ project.config.json
├─ package.json
└─ miniprogram\
   ├─ app.ts
   ├─ app.json
   └─ app.wxss
~~~

仓库根目录和内部源码目录都不是本项目的导入目录。不需要重新创建模板或选择其他前端框架。

AppID 按实际账号条件处理：

- 已有真实小程序 AppID：在导入界面填写，并确认当前登录微信具有对应项目的开发权限。让工具保存实际账号配置。
- 暂无 AppID：若当前工具提供“不使用 AppID”或游客入口，可先用于本地模拟器检查；若提供“测试号”，按工具引导申请或选择实际测试号。
- 工具若拒绝 touristappid，应使用工具提供的有效测试号或自己的小程序 AppID；不要编造 wx 开头的 ID。游客占位和平台分配的测试号不是同一个概念。

本轮没有代替用户选择账号，也没有自行填写真实 AppID。

## 3. 编译和本地模拟器

1. 导入后等待工具加载项目和基础库，打开“模拟器”和“调试器”。
2. 在“详情 → 本地设置”等对应位置核对基础库。优先使用项目配置的 3.15.0；如工具不提供该版本，从工具的版本列表选择可用的稳定基础库，再编译，并记录实际版本。
3. 工程已启用工具内置 TypeScript 编译插件。保留现有 .ts 文件，不需要手动生成同名 .js 文件。
4. 工具栏使用“普通编译”或默认启动方式，点击“编译”。默认进入 pages/forum/index。若之前保留了自定义编译条件，将启动页切回该路径。
5. 查看调试器 Console 是否有红色错误，随后按下节核对界面。

当前小程序运行时没有 npm 包依赖，PNG 资源也已入工程，因此不需要点击“工具 → 构建 npm”。开发者工具负责运行时编译；命令行 TypeScript 检查另行执行。

如需重新运行本地检查：

~~~powershell
Set-Location D:\CODE\XinKeLink\apps\miniprogram
npm.cmd ci
npm.cmd run check
node scripts/check-wechat.cjs 'D:\develop\微信web开发者工具'
~~~

这些命令不能替代模拟器运行或真机检查。

## 4. 当前应看到的效果

- 首屏为论坛容器，可见“信科Link / Forum”公共头部、“发现校园动态”和分类文字。内容区域尚无帖子，这是当前阶段的预期范围；分类交互也尚未开发。
- 底部呈现“论坛、交易、中央加号、联系、我的”五个位置。除中央按钮外，四个入口应可切换，选中状态跟随当前页面。
- 点击中央加号打开底部发布选择面板，包含“发布帖子”和“发布闲置”两张卡片。
- 点击遮罩或关闭按钮应关闭面板；点击面板内部非按钮区域应保持打开。
- 选择帖子或闲置后，面板关闭并分别提示“已选择发布帖子”或“已选择发布闲置”。当前不进入编辑器，也不提交内容。
- 其他 tab 仍为基础容器；“我的”尚无用户资料卡，交易和联系尚无商品或会话数据。

在模拟器选择一个常用手机尺寸，优先确认：

1. 公共头部是否避开右上角微信胶囊。
2. 底部导航是否完整可见、切换后选中是否正确。
3. 面板是否位于底部、遮罩是否覆盖导航、关闭和选择是否正常。
4. 底部安全区是否留出空间，有没有元素重叠或截断。

本轮保持现有视觉参数。字号、间距、圆角、图标和色值的进一步校准，等待高清截图和实际效果反馈。

## 5. 手机二维码预览

本地模拟器与手机预览是两项不同的检查。不要把配置中的 touristappid 当作已具备手机预览权限。

1. 先确认本地编译和上述核心交互正常。
2. 确认项目配置了具备相应权限的真实小程序 AppID，或按工具提供的实际测试号能力操作；当前登录微信需有对应开发权限。
3. 点击工具栏“预览”，等待工具完成编译并生成二维码。
4. 使用有项目权限的微信账号扫码，在手机中检查同一套头部、导航与发布面板。

如需查看手机端日志，可使用工具提供的“真机调试”。实际权限和扫码结果以工具及微信提示为准；本轮尚未生成预览二维码或完成真机检查。

本阶段页面无需真实后端连接，检查公共 UI 时无需启动管理后台、Java 服务或数据库。

## 6. 常见导入问题

| 现象 | 优先检查 |
| --- | --- |
| 找不到 app.json 或工程配置 | 导入目录是否为 D:\CODE\XinKeLink\apps\miniprogram，miniprogramRoot 是否仍为 miniprogram/ |
| 提示 app.js 不存在或 TS 文件无法运行 | 先确认目录，再检查工具版本和 typescript 编译插件；不要手工补造 app.js |
| 提示 AppID 无效或无权限 | 使用有效测试号或真实 AppID，并核对当前扫码登录账号的权限 |
| 基础库下载失败或 API 不可用 | 检查网络及工具基础库列表，选择可用稳定版本并记录实际版本 |
| 出现旧界面或启动页错误 | 保存文件、恢复普通编译，必要时使用工具内“清缓存 → 全部清除”后重新编译；不删除源码 |
| CLI 提示服务端口关闭 | 这影响命令行自动化；本次可直接通过工具界面手动导入、编译和预览 |

如仍无法运行，请保留第一条红色错误、所在页面和实际基础库版本；完整错误比单独的“编译失败”更便于定位。
